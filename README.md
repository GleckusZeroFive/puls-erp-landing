# PULS ERP — лендинг

Одностраничный сайт-витрина продукта PULS ERP: показывает продукт и
собирает заявки на ранний доступ.

Сделан на **Astro + Tailwind** — это обычные HTML/CSS/JS на выходе, без
привязки к платформе или конструктору. Поддерживать может любой
веб-разработчик; никаких закрытых инструментов не используется.

---

## Что нужно установить

- **Node.js** версии 22.12 или новее — <https://nodejs.org> (LTS).
  Проверить: `node -v`.

Больше ничего ставить не нужно — все библиотеки подтянутся одной
командой ниже.

---

## Запуск на своём компьютере

```bash
npm install      # один раз — скачать зависимости
npm run dev      # запустить локально
```

После `npm run dev` в консоли появится адрес вида
`http://localhost:4321/puls-erp-landing` — открыть его в браузере.
Правки в файлах применяются автоматически, перезагружать не нужно.

---

## Сборка готового сайта

```bash
npm run build
```

Собранный сайт кладётся в папку **`dist/`**. Это обычные статические
файлы — их можно положить на любой хостинг (см. раздел «Перенос на свой
сервер»).

Проверить сборку локально перед выкладкой:

```bash
npm run preview
```

## Форма заявок

Заявки с сайта уходят:

- в **Google-таблицу** (полный архив, выгрузка в Excel);
- на **почту** уведомлением о каждой новой заявке;
- (опционально) дублем в **Telegram** — сейчас не подключено, при
  необходимости включается без переборки кода.

Сама форма — часть сайта, а приёмник заявок вынесен в отдельный
маленький бесплатный сервис. Как он устроен, как сменить
почту/получателя и как развернуть заново — подробно описано в
**[`_server/README.md`](./_server/README.md)**.

Адрес приёмника задаётся одной строкой в файле `.env` (шаблон —
в `.env.example`):

```
PUBLIC_FORM_WEBHOOK_URL=https://script.google.com/macros/s/.../exec
```

Если строку оставить пустой — форма не ломается, а предлагает
отправить заявку письмом.

## Перенос на свой сервер и домен

Когда будете готовы переехать на собственный хостинг и домен
(например, `puls-erp.ru`):

1. **Изменить адрес сайта в настройках.** В файле `astro.config.mjs`:
   - `site` — поменять на ваш домен, например `https://puls-erp.ru`;
   - `base` — **удалить строку** (или поставить `'/'`). Сейчас там
     `'/puls-erp-landing'` только потому, что бесплатный хостинг кладёт
     сайт в подпапку. На своём домене сайт лежит в корне, подпапка не
     нужна — если это не убрать, картинки и стили «отвалятся». Это
     самый частый промах при переезде, поэтому отдельно подчёркиваю.

2. **Собрать:** `npm run build` → папка `dist/`.

3. **Выложить `dist/` на хостинг.** Подойдёт любой обычный хостинг для
   статических сайтов (на РЕГ.ру это тариф «хостинг», отдельный сервер
   для статики не обязателен). Содержимое папки `dist/` копируется в
   корневую папку сайта на хостинге (обычно `public_html` или `www`).

4. **Привязать домен.** В панели хостинга домен `puls-erp.ru`
   направляется на эту площадку. Если домен и хостинг у одного
   провайдера (РЕГ.ру) — это пара кликов в их панели; инструкция есть
   у них в разделе «Домены». HTTPS у большинства хостингов включается
   автоматически (бесплатный сертификат Let's Encrypt).

5. **Перенести приёмник формы** при желании — см. `_server/README.md`,
   раздел «Что когда-нибудь стоит улучшить» (свой домен для отправителя
   писем).

> Сервер с базой данных нужен продукту (ERP), а не лендингу. Лендинг —
> это набор готовых файлов, ему достаточно самого простого статического
> хостинга.

## Перенос в GitLab (по желанию)

Если код лендинга нужно держать рядом с остальным проектом в GitLab:

```bash
git remote set-url origin <адрес-вашего-GitLab-репозитория>
git push -u origin main
```

Автодеплой на GitHub Pages при этом перестанет работать (он привязан к
GitHub) — но это и не нужно после переезда на свой хостинг: там сайт
обновляется выкладкой папки `dist/` (пункты выше). При желании в GitLab
можно настроить аналогичный автодеплой через GitLab CI — это отдельная
небольшая задача.

## Структура проекта

```
production-site/
├── src/
│   ├── pages/index.astro       — сборка всех секций лендинга
│   ├── components/             — секции (Hero, дашборд, форма и т.д.)
│   ├── data/scenarios.ts       — данные интерактивного дашборда (3 роли)
│   ├── layouts/Layout.astro    — общий каркас страницы, мета-теги
│   └── styles/global.css       — палитра и шрифт продукта
├── public/                     — картинки, логотип, экраны продукта
├── _server/                    — приёмник формы заявок (+ своя инструкция)
├── astro.config.mjs            — адрес сайта (site / base) — см. «Перенос»
└── .env                        — адрес приёмника формы (не в репозитории)
```

Палитра и шрифт заданы в одном месте — `src/styles/global.css`:

- `#202F4D` — основной цвет (тёмно-синий);
- `#FF3A4A` — акцент (красный, кнопки);
- `#FFFFFF` фон, `#747476 / #D0D0D0 / #EFEFEF` — серые;
- шрифт **Onest**.

Тексты секций — в начале `src/pages/index.astro` и в
`src/data/scenarios.ts`.
